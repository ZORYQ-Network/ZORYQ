Build on ZORYQ

ZORYQ is an AI-ready Web3 Launch Network built around an EVM Testnet, mobile wallet, validator participation, quests, score and launch tooling. The product goal is to help builders move from an idea to a verifiable on-chain project with less infrastructure complexity.

ZQ and Testnet points have no guaranteed financial value. A future production token is optional and subject to product, security and legal gates.

ZORYQ Score

Score measures useful Testnet participation. Finalized score is written to the Reward Registry and is the source of truth for the wallet and Leaderboard. Pending estimates are clearly separated.

ValidatorHighest weight; healthy infrastructure and uptime
Contributor / BuilderQualified deploys, tooling and ecosystem contribution
MobileQuests, eligible stake/swap and Testnet use

Validator activity is designed to carry roughly 10x–25x the weight of ordinary mobile actions.

Quests

Quests are defined through the Quest Registry. Each quest has an ID, points, active period and status. Completion can be checked against chain activity or approved campaign evidence before score is finalized.

Sybil loops, wash swaps, self-transfers and faucet farming are not valid contribution.

Run a Node

The validator agent runs on Windows or Linux and does not require the operator wallet private key. Pairing uses a one-time wallet signature in the browser. The coordinator returns a separate Node ID and Node Secret used only for heartbeat authentication.

Pairing flow
1. Connect operator wallet on Run a Node
2. Sign registration challenge
3. Save zoryq-node.json
4. Start zoryq-validator(.exe)
5. Agent reads eth_blockNumber
6. Authenticated heartbeat every 60s
7. Pending validator score → epoch review → on-chain finalization

The coordinator rejects stale timestamps, invalid HMACs, unknown nodes and node block heights far from the current chain.

Leaderboard

The global ranking is rebuilt from finalized Reward Registry events. It supports Global, Validator, Builder and Mobile views, wallet profiles and level progression. Pending node estimates do not count as finalized rank.

Launch Studio

Launch Studio creates a versioned project manifest containing token, NFT and quest parameters. It never collects private keys and requires human approval before any deployment. The current Alpha produces reviewable/downloadable manifests while production deployment templates remain gated behind public RPC and contract security checks.

JSON-RPC

The gateway supports standard Ethereum JSON-RPC and blocks administrative namespaces such as anvil_*, hardhat_*, evm_* and debug_*.

curl -X POST https://zoryq-evm-node-v4-production.up.railway.app/rpc \
-H 'content-type: application/json' \
--data '{"jsonrpc":"2.0","id":1,"method":"eth_chainId","params":[]}'

Common methods: eth_chainId · eth_blockNumber · eth_getBalance · eth_getCode · eth_call · eth_sendRawTransaction · eth_getTransactionReceipt · eth_getLogs.

Smart contracts

ZORYQ supports standard Solidity bytecode. Use Remix, Foundry, Hardhat, ethers or viem with Chain ID 5919065. Deployment keys must be disposable Testnet keys or connected wallets.

export ZORYQ_RPC=https://zoryq-evm-node-v4-production.up.railway.app/rpc
forge create src/MyContract.sol:MyContract --rpc-url $ZORYQ_RPC --private-key $TESTNET_PRIVATE_KEY

ERC-20

Standard ERC-20 contracts can be deployed on the Testnet. Future production token tooling is sale-disabled by default and subject to tokenomics, security and legal approval gates.

Security model

ZORYQ EVM Testnet is currently a centralized public testing environment, not a production Mainnet consensus network. Administrative JSON-RPC namespaces are blocked publicly. The node service starts Anvil with zero embedded accounts; the faucet changes balances only through the local administrative endpoint. Wallet seeds and private keys must never be committed, uploaded or placed in public infrastructure.

Validator Node Secrets are not wallet keys, but they authenticate heartbeats and must remain private. Production treasury and eventual token controls should use multisig and audited contracts.
