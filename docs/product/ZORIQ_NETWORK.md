# ZORIQ Network Strategy

## Decision
ZORIQ launches **multichain first**. A ZORIQ-native network is planned as an optional future execution layer after measurable adoption and revenue.

## Why not a new L1 now
A new L1 would require bootstrapping security, validators, liquidity, bridges, RPCs, indexing, exchange/wallet integrations and developer distribution while the core consumer product is still growing.

## Preferred future architecture
When justified, evaluate an Ethereum-aligned **L2/appchain/rollup stack** rather than creating a consensus network from zero.

## Chain-abstraction rule
The app must treat chains as capabilities. ZORIQ ONE chooses the best permitted route based on user intent, cost, latency and Guard risk analysis. ZORIQ Network should win routes because it is better, not because the user is locked in.

## Native ZORIQ capabilities to target
- account abstraction and sponsored gas;
- ZORIQ ID resolution;
- Guard-aware transaction policies;
- low-cost SocialFi/XP state transitions;
- batched intents;
- transparent execution-fee accounting;
- bridge allowlists and emergency controls.

## Launch gates
Do not launch mainnet until:
- public testnet has sustained uptime;
- independent audits cover chain-specific contracts/bridges;
- incident and escape procedures are tested;
- explorer/RPC/indexers are redundant;
- economics are modeled and reviewed;
- the existing ZORIQ app has enough users/volume to seed real demand.
