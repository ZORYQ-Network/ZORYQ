# Architecture Decision Records

Use ADRs for durable engineering decisions that affect architecture, protocol semantics, security boundaries or long-term maintenance.

## Naming

`ADR-NNN-short-title.md`

Examples:

- `ADR-001-consensus.md`
- `ADR-002-state-model.md`
- `ADR-003-execution-engine.md`

## Template

```md
# ADR-NNN — Title

Status: Proposed | Accepted | Superseded | Rejected
Date: YYYY-MM-DD

## Context

## Problem

## Options considered

## Decision

## Why

## Trade-offs

## Security implications

## Performance implications

## Compatibility implications

## Alternatives rejected

## Evidence / references
```

ADRs must describe real decisions. Do not create placeholder ADRs solely to make the repository appear mature.
