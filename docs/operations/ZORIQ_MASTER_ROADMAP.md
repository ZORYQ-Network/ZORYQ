# ZORIQ Master Roadmap — Adoption, Revenue and ZORIQ Network

## Product thesis
ZORIQ launches **multichain first**. Users should be able to use Bitcoin, EVM networks and Solana without learning chain mechanics. A proprietary chain is a later optimization, not a prerequisite for adoption.

Sequence:
`Users -> Wallet/Swap -> Revenue -> ZORIQ ONE/Guard/ID -> B2B APIs -> ZORIQ Network`

## Phase 0 — Foundation (now)
- ZORIQ brand across mobile, docs and Android/iOS metadata;
- Android APK generated by GitHub Actions;
- self-custody wallet architecture and secure-storage boundary;
- automatic language/region detection + manual override;
- wallet, swap, SocialFi, Spotify, XP and settings UI;
- ZORIQ ONE and Guard preview flows;
- official treasury registry for EVM, Solana and Bitcoin;
- fee disclosure with revenue mode defaulting to `preview`.

**Exit gate:** reproducible APK, brand migration complete, no seed/private key in repository.

## Phase 1 — Revenue-capable beta
### ZORIQ Route
- production-capable quote/routing provider;
- ZORIQ integrator account;
- correct treasury per network namespace;
- transparent target fee of **15 bps / 0.15%** on eligible routes;
- reconciliation of gross fee, partner share and net ZORIQ revenue.

### ZORIQ Pro
- store billing + entitlement layer;
- Founders pricing hypothesis: **US$4.99/month** or localized equivalent;
- advanced Guard, portfolio intelligence, routing controls, ONE automations, alerts and premium customization;
- no paid benefit implies guaranteed airdrop/token allocation.

### Growth revenue
- partner referrals only where terms permit;
- anti-sybil/anti-self-referral controls;
- sponsored quests clearly labeled when introduced.

**Exit gate:** first reconciled route-fee transaction and/or first paid Pro subscription.

## Phase 2 — Controlled mainnet
- limited chain/token allowlist;
- real transaction simulation in Guard;
- backend quote ids + TTL;
- route and fee kill switches;
- canary settlement for every treasury namespace;
- staged user cohorts;
- production monitoring + incident response.

## Phase 3 — Social distribution
- SocialFi backend with moderation/report/block;
- creator discovery and communities;
- notifications and invite loops;
- Spotify production OAuth;
- useful-activity XP instead of passive farming;
- referral attribution + abuse scoring.

## Phase 4 — ZORIQ ONE + ZORIQ ID
- `@username` identity;
- verified multi-network address mapping;
- chain/asset destination preferences;
- intent planner and solver abstraction;
- cross-chain execution planning;
- Guard before every high-risk signature.

## Phase 5 — B2B monetization
Launch **ZORIQ Guard API** and **ZORIQ ONE API** for wallets, dApps and fintechs.

Revenue models:
- metered API usage;
- monthly developer plans;
- enterprise SLA/support;
- transaction/routing revenue share where contractually permitted.

**Exit gate:** an external partner pays to use ZORIQ technology independently of the consumer app.

## Phase 6 — ZORIQ Network research gate
Do **not** launch a new L1 merely for branding. Start network engineering only when product traction makes infrastructure ownership economically or technically useful.

Signals:
- sustained active-wallet growth;
- meaningful monthly routed volume;
- recurring ZORIQ revenue;
- material third-party execution fees;
- clear need for cheaper/faster ZORIQ-native execution;
- enough distribution to avoid an empty chain.

Architecture preference: **Ethereum-aligned L2/appchain/rollup stack**, not a new L1 from scratch.

## Phase 7 — ZORIQ Network testnet
- choose mature rollup/appchain stack after security/economic review;
- public testnet;
- account abstraction/paymaster policy;
- Guard as default safety layer;
- ZORIQ ID native resolution;
- bridge allowlists + emergency controls;
- explorer/RPC/indexing/monitoring;
- sequencer/validator decentralization roadmap;
- treasury/revenue accounting isolated from user funds.

The app remains multichain. ZORIQ Network is selected when it is objectively a better route, not because users are forced onto it.

## Phase 8 — ZORIQ Network mainnet
Launch only after audits, testnet stability, bridge review, emergency procedures and sufficient product demand.

Potential advantages:
- execution-layer revenue;
- lower cost for ZORIQ-native actions;
- better UX for SocialFi/XP/identity;
- programmable fee sponsorship;
- deeper ONE/Guard/ID integration.

## North-star metrics
- monthly active wallets;
- funded-wallet activation rate;
- routed swap volume;
- successful transaction rate;
- gross/net ZORIQ fee revenue;
- Pro conversion/MRR/churn;
- 30-day retention;
- Guard analyses and prevented high-risk actions;
- verified ZORIQ IDs;
- B2B customers and MRR.

## Non-negotiables
- no seed/private key in ZORIQ backend, GitHub or analytics;
- all fees disclosed before signature;
- treasury selected by network namespace;
- XP is not a promise of token allocation;
- network launch never precedes security and product-market fit.
