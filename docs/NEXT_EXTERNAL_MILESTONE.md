# Next External Milestone

The first independent developer transaction proof is complete. The next external milestone should not be another internal feature; it should be independent usage that deepens the evidence.

## Priority order

1. **Independent Node 2** — separate operator/control boundary, persistent state, peers/convergence/restart evidence.
2. **External contract/application** — source not authored by the primary ZORYQ operator, deployed and usable through public infrastructure.
3. **Autonomous Company reproduction** — external user completes the narrow evidence-backed flow when the vertical slice is ready.
4. **Design partner pilot** — real external workflow with measurable success criteria.
5. **Paid pilot/customer** — payment actually received for a defined service/pilot.

## Why this order matters

A second internal demo adds less fundraising credibility than a first external operator, external app or paying user. ZORYQ should optimize for independent evidence before adding breadth.

## Current external proof

Completed Issue #88 demonstrates:

`public RPC -> public faucet -> fresh wallet -> signed transaction -> receipt status=1`

It does not prove distributed operation or product-market fit.

- another internal feature, or
- removing friction for an independent builder/operator/customer,

prefer the second unless the internal feature is a direct blocker to external reproduction, safety or reliability.
