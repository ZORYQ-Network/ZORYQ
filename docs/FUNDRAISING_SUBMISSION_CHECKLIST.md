# Fundraising Submission Checklist

This checklist separates work already prepared from information that must come from the founder before any real application can be submitted truthfully.

## Prepared

- [x] investor-ready project thesis
- [x] verified external traction record
- [x] monetization hypotheses
- [x] accelerator application answer bank
- [x] Alliance application draft
- [x] LAUNCH Accelerator application draft
- [x] Digital Science Catalyst 2026 proposal draft
- [x] ARIA Scaling Trust Track 2.2 proposal draft
- [x] builder acquisition challenge
- [x] pilot intake flow
- [x] external builder evidence template
- [x] outreach message bank

## Founder / company information required before submission

- [ ] founder legal name
- [ ] founder email used for applications
- [ ] country of residence / application location
- [ ] legal entity name and registration status (if any)
- [ ] ownership / cap table
- [ ] team members and roles
- [ ] full-time / part-time status of founder and key team
- [ ] prior capital raised
- [ ] current revenue, if any
- [ ] monthly burn and runway
- [ ] current fundraise target
- [ ] preferred financing instrument, subject to legal advice
- [ ] founder biography / relevant background

## Programme-specific blockers

### Alliance

- [ ] founder identity/contact
- [ ] entity/cap table/funding history
- [ ] team information
- [ ] confirm live investment terms at submission time

### LAUNCH Accelerator

- [ ] founder/team profile
- [ ] current financing information
- [ ] confirm live Cohort 37 terms and deadline/status at submission time

### Digital Science Catalyst 2026

- [ ] decide whether ZORYQ will genuinely pursue the research-specific workflow
- [ ] founder/team section
- [ ] one real research workflow/user persona
- [ ] competitor analysis
- [ ] budget up to the programme limit
- [ ] ideally stakeholder interviews or research-domain design partner

### ARIA Scaling Trust Track 2.2

- [ ] founder/team bios and time commitments
- [ ] open-source/IP plan
- [ ] security/formal-methods collaborator or credible hire plan
- [ ] UK benefit / UK operation or collaboration plan
- [ ] detailed related-work comparison
- [ ] eligible-cost budget spreadsheet
- [ ] commercial hypothesis
- [ ] final proposal formatted to ARIA requirements

## Submission rule

Do not invent founder data, revenue, customers, partnerships, legal status, team credentials, funding history or UK commitments to make an application look stronger.

An application is ready to submit only when every field that represents a real-world fact has been confirmed by the founder or supported by public evidence.
