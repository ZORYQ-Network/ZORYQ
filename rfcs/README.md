# ZORYQ RFC Process

Major protocol, security, API, execution, state, networking or developer-platform changes should begin as an RFC before being treated as accepted architecture.

## Status flow

`DRAFT → REVIEW → EXPERIMENTAL → ACCEPTED → IMPLEMENTED`

An RFC may also become `REJECTED`.

## RFC template

```md
# RFC-NNN — Title

Author: <real author(s)>
Status: DRAFT
Created: YYYY-MM-DD

## Summary

## Motivation

## Problem

## Design

## Alternatives

## Security considerations

## Performance considerations

## Compatibility

## Testing plan

## Benchmark plan

## Rollback / migration

## Open questions

## Related work
```

`ACCEPTED` means the design decision is accepted. `IMPLEMENTED` requires linked code and tests. Performance claims require linked benchmark evidence.
