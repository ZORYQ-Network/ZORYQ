ZORYQ is an EVM-compatible public testnet focused on agent-native developer tooling, verifiable builder intelligence and native DeFi, designed to reduce the path from idea to verifiable on-chain product.

## Why this fits Origins
Origins explicitly welcomes DeFi, infrastructure and AI projects. ZORYQ intersects all three:
- EVM infrastructure and public RPC/Explorer;
- native DEX, Lending, Stake and Project Registry;
- agent-readable schemas and machine-readable chain context;
- Project Intelligence and Builder Reputation primitives.

## Demo flow (90 seconds)
1. Open `/start` and add ZORYQ EVM Testnet.
2. Connect a standard EVM wallet.
3. Claim test ZQ.
4. Execute a ZQ/zUSD swap on `/swap`.
5. Open the confirmed transaction in `/explorer`.
6. Open `/developer` and show the five-minute Foundry/viem/ethers path.
7. Open `/intelligence` and explain verifiable builder/project activity.
8. Open `/network-maturity` and explicitly disclose that the current public testnet is centralized and not production-ready Mainnet.

## Differentiator
Most EVM networks compete primarily on throughput and fees. ZORYQ's wedge is developer velocity plus an agent-readable execution environment where builders can move from wallet connection to contract deployment, verifiable activity, project identity and reputation with fewer disconnected tools.

## Evidence policy
Do not claim:
- decentralized or multi-validator production network;
- audited protocol suite;
- Mainnet readiness;
- monetary value for ZQ/zUSD;
- guaranteed token or airdrop;
- finalized on-chain Genesis Score.

## What to build during the hackathon if accepted
Prioritize a compact, externally useful extension rather than rebuilding the chain:
1. public Project Registry viewer;
2. agent action demo that reads registry + DEX state and prepares a user-confirmed transaction;
3. builder activity proof page tied to transaction receipts;
4. polished mobile onboarding;
5. reproducible public starter repository.

## Application narrative
ZORYQ is already a working EVM-compatible testnet with a public RPC, Explorer and native DeFi. The project is now moving from infrastructure construction to external developer and user acquisition. Origins would be used to ship the missing distribution layer: a clean public starter, an agent-native builder demo and verifiable project reputation using live on-chain activity.
