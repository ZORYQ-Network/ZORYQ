# ZORYQ Growth Scorecard

This scorecard exists to prevent feature-building from being confused with adoption. Only externally verifiable evidence should move the distribution and traction scores.

## Current working baseline

- Distribution: 38 / 100
- External traction: 24 / 100
- Network maturity: 46 / 100
- Investor readiness: 64 / 100

These are management scores, not protocol metrics and not public claims.

## Distribution — target 60+

Evidence that moves the score:

1. Chain registry PR merged.
2. Public-source developer package accessible without repository invitation.
3. Builder Challenge published.
4. 10 independent developers reached through relevant channels.
5. At least 3 external ecosystems/directories link to ZORYQ.
6. Repeatable public onboarding URL with locale detection.
7. Developer documentation linked from every product surface.

Do not count internal posts, self-interactions, repository commits or Treasury transactions as distribution.

## External traction — target 45+

Evidence that moves the score:

1. First independent wallet completes faucet + on-chain action.
2. First independently deployed contract.
3. First external dApp.
4. First Project Registry project not controlled by Treasury/team.
5. Five independent active wallets.
6. Ten independent developers.
7. Second-week repeat activity from external wallets.

Treasury/self-interactions are excluded from external traction.

## Network maturity — target 60+

Evidence that moves the score:

1. Independent-node architecture/specification documented.
2. Reproducible local boot process validated by someone outside the core operator.
3. Consensus implementation selected and threat model documented.
4. Three independently operated devnet nodes.
5. Restart/catch-up test passed.
6. Single-node outage does not halt the devnet.
7. Partition/recovery test passed.
8. Public RPC failover demonstrated.

Registration/heartbeat observers do **not** count as consensus validators.

## Investor readiness — target 80+

Evidence that moves the score:

1. Investor page with verifiable proof and explicit risks.
2. Current pitch deck.
3. Technical brief/data-room index.
4. Clear founder/entity/funding information.
5. Clear use-of-funds model.
6. External traction evidence.
7. Public technical package.
8. Accelerator/investor applications submitted.
9. Credible multi-node execution roadmap.
10. First external builders/projects.

## Weekly operating rule

Every new feature should answer at least one of these questions:

- Will this get an external builder to deploy?
- Will this get an external user to complete an on-chain action?
- Will this create verifiable network-maturity evidence?
- Will this materially reduce investor diligence friction?

If the answer is no to all four, it is not a priority unless it fixes a security/reliability problem.
